# 予页 pagetoyou

本机完整体验版 v1.0.0-rc.1：统一礼物模板库、真实账号、个人中心和发布快照。照片树现使用真实 WebGL 金属球体、照片实体、环境反射与泛光，可聚合为树或散开为照片星云。尚未部署公网。

私有仓库：[doojinn/pagetoyou](https://github.com/doojinn/pagetoyou)。本版为发布候选；公网应用尚未部署。完整验收记录见 [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md)，部署说明见 [DEPLOYMENT.md](DEPLOYMENT.md)。

## 运行

安装 Node.js 24+ 后，在此目录运行 `npm start`，浏览器打开 http://127.0.0.1:4175 。无需安装依赖。默认只监听本机；运行时自动创建 .data/pagetoyou.sqlite，并可读取 .env（可参考 .env.example）。数据库、会话和用户照片不会进入 Git。浏览器本地草稿仍按当前地址隔离。

账号使用账号名与密码注册，不要求邮箱服务；可在个人中心验证当前密码后生成离线恢复码，用于忘记密码时重设。恢复码仅展示一次、有效期一年；重新生成或成功找回后旧码失效。密码以加盐 scrypt 哈希保存，会话使用 HttpOnly Cookie。修改密码会使其他登录会话失效。

## 信封与书信更新

新建礼物先挑选信封，再选择礼物类型。12 款信封包括棉笺、雾蓝、鼠尾草、玫瑰印花、压花、绣球纸艺、旧金羊皮纸、楮皮纸和绳结等；支持循环滑动、方向键与自定义火漆颜色。拆封依次解绳／移除火漆、翻开封舌、抽出信纸。绳结可点击或拖动解开，属于分层动画，不是物理模拟。

新增银杏叶礼物（翻面留言）、羊皮纸长信及四种贺卡内页。已接入原有账号草稿与发布快照；旧礼物没有信封字段时仍能打开。素材与生成提示词见 [素材说明](assets/stationery/README.md)。

## 照片展墙与空间

照片长廊使用多排绳挂展墙，可更换陈列风格与照片背景。3D 照片空间使用 Three.js，鼠标旋转、右键平移、滚轮／双指缩放，点击相片后可详细放大。开场可选“穿行 → 聚合 → 绽放”或直接探索。摄影风格示例为生成素材，上传照片不复制补量。

## 当前能力

- 3D 文字空间：编辑祝福，每行一句；文字球体自动旋转、拖动转向、缩放、暂停。
- 3D 照片树：多张照片沿树排列，可旋转和点击放大。
- 3D 照片空间：照片在立体空间分布，拖动、缩放和点击放大。
- 幻灯照片故事：淡入、滑入、推近三种过渡，手动翻页或自动播放。
- 互动生日蛋糕：点击许愿、熄灭蜡烛、显示祝福。
- 聊天回忆墙：上传截图后排列和放大查看；不提供聊天账号导入或 OCR。
- 电子相册：按钮翻页、左右滑动及键盘方向键切换。
- 照片长廊：横向滑动、点击放大。
- 标题、署名、文字和空间配色编辑，真实本地照片上传与压缩、配文、排序和移除。
- IndexedDB 保存和恢复一份当前草稿，包含照片；仅保存在此浏览器。
- 信封贺卡可保存布局到账号、从个人中心恢复并发布；原编辑器的照片仍是示例元素，真实照片编辑与独立浏览器草稿待统一。
- 保存到账号、发布或更新发布，生成独立收礼地址；未登录浏览器可只读查看。
- 个人中心：全部/草稿/已发布/已停止，编辑、发布、停止分享、删除、昵称和密码设置。
- 草稿与发布快照分离；修改草稿不会改变已发出的内容。停止分享或删除后，原链接再次访问失效。

照片树使用本地固定的 Three.js 0.180.0（vendor/three，MIT 许可证），其余模板保留 CSS 或 Canvas 方案。无需额外 npm 安装，运行不从外部 CDN 加载图形库。图形硬件不支持 WebGL 时会回退为基础粒子树；完整效果建议启用浏览器硬件加速。示例照片为程序绘制的风景占位图，可移除后上传自己的图片。照片模板最多 30 张（含示例图），单张原图不超过 10 MB；信封贺卡原编辑器保留最多三张限制。动画尊重减少动态效果偏好。

树内操作：鼠标拖动旋转、右键拖动平移、滚轮缩放；触摸端可单指旋转、双指缩放/平移。底部提供散开/聚合、靠近、退远、暂停及重置。点击照片可放大，画质下拉可在流畅与精细之间切换。当前不提供摄像头手势识别。

模板库中有九类礼物。发布弹窗明确区分本机地址与配置的公网地址，不把 localhost 链接称为朋友可远程访问的礼物。试用期每账号最多 50 份，单份内容请求限 16 MB。

## 检查

`npm run check` 检查脚本语法，`npm test` 验证账号、权限、修订冲突、发布快照、停止/删除和重启持久化。测试数据库写在被忽略的 .document-work 目录，不使用真实用户数据库。

## 部署边界

当前最直接的部署方式为带持久化磁盘的 Node.js 主机，并通过 HTTPS 反向代理访问；公网地址配置在 PUBLIC_ORIGIN，监听地址由 HOST 配置。仅填写公网域名不等于完成托管、DNS 和 HTTPS。

若坚持 GitHub Pages 托管前端，仍需单独部署后台并适配跨站 API、会话及收礼路由；本版本尚未进行该适配，不应直接把后台代码放到 Pages 后声称登录可用。最终在线方案待确认。

备份需覆盖 .data 下数据库及关联文件，建议先正常停止服务再备份。不要删除 .data 来更新代码，否则会丢失账号和礼物。
